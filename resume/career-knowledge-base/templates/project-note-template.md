# 项目复盘模板

## 一句话定位

这个项目解决什么问题，面向什么用户或业务场景。

## 背景与痛点

- 原来的流程或系统有什么问题。
- 为什么需要自动化、平台化或工程化改造。
- 这个问题对效率、质量、稳定性或协作造成了什么影响。

## 我的职责

- 我负责的模块、流程或团队职责。
- 我做出的关键设计或决策。
- 我参与的实现、测试、部署、排障或管理工作。

## 技术架构

```text
用户 / 调度入口
-> API / 平台层
-> 执行层
-> 结果 / 报告 / 回调
-> 展示 / 复盘 / 决策
```

## 核心流程

- 输入：参数、配置、数据、触发方式。
- 处理：主要模块和调用链。
- 输出：结果、报告、状态、告警或质量指标。

## 难点与取舍

- 遇到的 2-3 个关键难点。
- 当时有哪些可选方案。
- 为什么最终选择这个方案。
- 这个方案的局限和后续改进点。

## 结果与价值

- 效率提升。
- 质量提升。
- 稳定性提升。
- 可维护性提升。
- 团队协作或交接改善。

## 面试表达

### 3 分钟版本

用背景、职责、技术方案、难点和结果快速讲清楚。

### 8 分钟版本

展开架构、关键流程、排障案例和取舍。

### 15 分钟版本

结合系统设计、团队协作、质量度量和后续演进。

## 面试追问

- 为什么这样设计？
- 如果规模扩大怎么办？
- 如何排查失败？
- 如何保证数据一致性？
- 如果重做，你会改什么？
