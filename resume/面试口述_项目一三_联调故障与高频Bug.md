# 面试应对：项目一、项目三未完成时，怎么讲联调问题和高频 Bug

项目一、项目三都还不是全组天天在用的完成态，**不要编「上线三个月、凌晨被叫起来」这种故事**。面试官追问时间、日志、谁验证，编的会穿。

正确拆法：

| 面试官要听的 | 你用哪一类事实 |
|---|---|
| 你会不会查问题 | 仓库 `issue/` 里已经发生过的部署 / 联调问题（下面 A 类，优先讲） |
| 闭环挂了你知不知道从哪层查 | 架构里已经按层分好的故障（下面 B 类，讲排查顺序） |
| 若系统真跑满，还会出什么 | C 类：高频剧本，用「这类问题我准备这样查」，不要说成上周线上刚炸 |
| 真正的业务失败分析 | **项目二**每天 CIT/CRT：环境 / 脚本 / 产品，这才是你最完整的排障经历 |

开场可以先定调（10 秒）：

> 平台和 MCP 还在按模块往前收口，不是全组生产默认入口。联调、部署、契约上我遇到过具体问题；完整每天看红灯、分环境还是脚本还是产品，是项目二的回归工作。如果问平台挂了怎么查，我按页面、接口、Jenkins、执行机、回调这几层对同一条任务编号。

---

## 0. 被问「讲一个你们遇到的疑难 Bug」时怎么选故事

优先顺序：

1. **A 类（真实发生过）**：NTP、Allure CLI、log.html 被 CSP 拦住、Debian 要代理才能拉代码、创建和触发分开。细节在仓库 issue 里，你讲得出来。
2. **项目二**：一条 CIT 失败，抓包或日志证明是环境 / 脚本 / 产品。这是 2019 年以来的本职，比平台更经得起追问。
3. **B / C 类**：对方明确问「页面绿、Jenkins 红怎么办」「回调丢了怎么办」。用分层排查，结尾加一句：这条主链路我按契约和服务器验证在推，全环境天天跑还没收到那个程度。

不要说的话：

- 「平台已经稳定运行、这些问题都在生产修过。」
- 把 C 类剧本的时间、人名、构建号编出来。
- 把 KPI 检测误报、MCP 全组误用说成已经发生的大规模事故。

## A 类：仓库里真实出现过的问题（优先当 STAR 讲）

出处：`C:\TA\jenkins_robotframework\issue\`。面试用现象 + 原因 + 你怎么处理，不必报内部 IP。

### A1. Debian 时间不准，任务时间和日志对不齐

**现象：** 服务器时间和笔记本差十几分钟。`timedatectl` 时区已是上海，但显示时钟未同步。手工改时间报「已开启自动同步」；`timesyncd` 访问公网 NTP 超时。

**原因：** 不是时区配错，是机器访问不了公网 NTP（公司网策略 / 应走内网 NTP）。

**处理：** 关掉无效的自动同步，手工把时间和硬件时钟对准；后续应改内网 NTP。在此之前，看 run 的创建时间、Jenkins 时间和日志时间不要当成同一套钟。

**面试官在探什么：** 你会不会把「对不上」先怀疑成代码 bug。  
**你可以补一句：** 平台要对页面、库、Jenkins 三条记录，时钟不准会误判回调延迟，所以部署后我先看 `date`。

### A2. pytest 过了，本机却打不开 Allure 报告

**现象：** `pytest --alluredir=allure-results` 通过；一敲 `allure serve` 提示 command not found。有人还会 `pip install allure` 失败。

**原因：** `allure-pytest` 只负责生成结果目录；看报告要 Allure CLI。Jenkins 后面用插件吃 `allure-results`，执行机不一定要装 CLI。

**处理：** 这一阶段只保证结果目录产出，报告交给 Jenkins Allure 插件。文档里把「生成结果」和「本机预览报告」写成两步。

**面试官在探什么：** 工具链边界清不清楚。  
**口误避免：** 不要说「我装了 allure 包就行」。

### A3. 门户里点 Robot 的 log.html，提示 Opening Robot Framework log failed

**现象：** Jenkins 已经归档了 `log.html`，文件在，页面打不开。

**原因：** Jenkins 对 artifact 默认加了很严的 CSP，禁止内联 JS。Robot 的 `log.html` 靠内联脚本渲染，所以被浏览器拦了。这是安全默认值的副作用，不是 log 损坏。

**处理：** 在 Nginx 反代 Jenkins artifact 的 location 里去掉 CSP 头（只动 artifact 路径，不动 Jenkins 主界面）。备选才是改 Jenkins 全局 CSP。

**这句话很好用：** 问题不在 Robot 没生成 log，而在「谁把文件交给浏览器、带了什么响应头」。

### A4. 服务器 clone / pull GitHub 失败

**现象：** Debian 上 git clone GitHub 连不上。

**原因：** 出网要走公司 HTTP 代理，不能直连。

**处理：** 给 git 配代理后再拉。同类还有 `git pull --ff-only` 失败：服务器上有本地改动，不能直接 `reset --hard`。

**面试官在探什么：** 内网部署常见坑。点到为止，不要展开代理地址。

### A5. 为什么创建任务和触发 Jenkins 要拆成两步（设计来自真实联调）

**现象：** 若「创建 + 触发」绑死在一个按钮里，Jenkins 一失败，页面上什么记录都没有，用户只能再填一遍；也分不清是参数没过、还是 Job 没打出去。

**处理：** 先 `POST` 创建 run，落到 SQLite，拿到稳定 `run_id`；再单独 trigger。触发失败时记录仍在，详情页可以重试触发。业务主键不用 Jenkins 的 queue/build 号。

**面试怎么讲：** 这是联调里刻意做的恢复设计。对应门户详情里「创建成功但触发失败可以 Retry」。

### A6. Allure / 测试依赖装错包（可跟 A2 合并讲）

`pip install allure` 不是 pytest 插件。Python 侧是 `allure-pytest`，CLI 是另一套。说明你会区分「测试框架插件」和「报告引擎」。

## B 类：完成态之前就已经按「分层」准备的查法

来源：可靠性设计（故障分成平台接口、Jenkins、检出、Python 环境、Runner、Robot、设备、KPI 后处理、回调）。面试时画这条链，比编一个故事更有说服力。

```text
人在门户看到的状态
  -> FastAPI / SQLite 里这条 run
  -> Jenkins build / console
  -> 执行机 workspace / Robot 或 Runner
  -> 产物是否归档
  -> callback 是否回来、字段是否对上
```

口头固定句：

> 我不看一个红灯就改代码。先看失败停在哪一层，再拿同一条 run_id 去对页面、库、Jenkins。单任务失败不应毁掉别的记录；触发失败应还能查、还能重试。

下面每个「Bug」都用同一套：现象 → 先查哪 → 根因候选 → 怎么处理 → 面试时怎么承认完成度。

## C 类：若闭环跑满，面试高频会问的 Bug（排查剧本）

**用法：** 「这种不一致我按下面顺序查。」  
**禁止：** 「上周生产就遇到，构建号是 1234。」  
若对方问「你亲自碰到过吗」：能对上 A 类的就说碰到过；只能对上 C 类的就说「主链路按这个设计在验，完整天天跑还没收到这一层」。

### 项目一

#### C1. 页面显示成功，Jenkins 是红的（或反过来）

**现象：** 门户绿、Jenkins 红，或门户还在 running、Jenkins 已结束。

**先查：** 同一 `run_id` 在 SQLite 的状态、Jenkins build 号、最后一次 callback 时间。是 trigger 没打出去、callback 没到、还是到了但状态机没更新。

**常见根因：** 回调脚本失败或超时；Nginx / 防火墙拦了 callback；页面缓存了旧状态；创建成功但 trigger 失败，页面只看了「有记录」。

**处理：** 详情提供重试触发；以 Jenkins 和产物为准做一次人工对账；修回调后再看库是否追上。

**完成度口径：** 创建 / 触发分离、详情可重试，是为这个问题准备的。

#### C2. 回调丢了、重复回调、先到后到

**现象：** 执行其实成功，库里一直 running；或成功后又被一次旧回调打成失败。

**先查：** Jenkins 里 callback 步骤日志、平台接收到的 payload、是否同一 `run_id`。

**常见根因：** 执行机访问不到 API；只回调了成功路径；没有幂等，重放覆盖终态。设计文档写过：回调还要补幂等键，**不要说已经做成恰好一次投递**。

**处理：** Jenkins 侧本地留一份 callback 结果；失败可重试；平台拒绝用旧 payload 覆盖明确终态（若代码还没做到，就说这是已知后续）。

#### C3. Jenkins 成功，产物链接 404 或 KPI 页是空的

**现象：** Job 绿，详情里点 log / Excel 没有，或 KPI 对比没有数。

**先查：** artifact 是否归档、路径是否写进 callback、API `/artifacts` `/kpi` 回什么、文件是否还在 workspace 被清掉。

**常见根因：** 归档步骤在失败时被跳过；路径写相对目录，门户按另一套拼 URL；Robot 失败时没有 log 仍去拼固定文件名；KPI 后处理没跑却当成功。

**处理：** 回调只带清单和元数据，大文件仍放 Jenkins/磁盘；没有产物时页面明确「未归档」，不要假成功。

#### C4. 点一次出现两个 Jenkins 构建

**现象：** 用户连点，或刷新后重复 trigger。

**先查：** 该 `run_id` 是否已有 build 号；状态是否允许再次 trigger。

**设计：** 仅 `created` / `trigger_failed` 允许再触发。若仍双开，查前端有没有 disable 按钮、接口有没有按 run 防重。

#### C5. SQLite 锁住 / 同时好几个人点任务

**现象：** 偶发数据库 locked，或列表偶发看不到刚建的任务。

**先查：** 是否多进程写同一个文件库；有没有把大日志写进 SQLite。

**口径：** SQLite 存元数据、大文件外置，是部署简单和容量之间的取舍。并发变大要考虑换库。**不要说已经上了高可用集群。**

#### C6. 两条 KPI 任务抢同一套测试资源

**现象：** 并行一开，设备状态乱、KPI 窗口对不上。

**先查：** 工作流是否把不能并行的步标成并行；Runner 资源锁有没有按 UE / 设备 / KPI 后处理域来。

**口径：** 前端勾选并行不等于无条件并行；危险组合加载时拦截，锁按固定顺序拿，减少死锁。当前是单进程锁，**不要说成跨机器分布式锁**。

#### C7. Robot 失败，RCA 给了错误分类

**现象：** 明明是环境连不上，摘要写成产品 bug。

**先查：** 分析用了哪些证据（console、output.xml、KPI 摘要）；规则 / 模型版本；人工有没有改过结论。

**处理：** RCA 只是辅助；人工复核。外部模型不可用时走规则。AI 不能自动重跑、不能自动关单。

**真实可讲：** 契约上就禁止 AI 当发布结论。分类错了是预期要人挡的，不是「模型已经很准」。

#### C8. Cursor 生成的接口和页面字段不一致

**现象：** 前端提交的 JSON 和 FastAPI schema 对不上，422 或库里缺字段。

**先查：** 以冻结的 schema 为准，看是页面多传了、还是后端改了字段没改页面。

**处理：** 一步只改一侧；联调检查单就是同一 run_id 对页面、库、Jenkins。这是你用 Cursor 时最该讲的「过程 Bug」，而且和未完成不冲突——每一步联调都会碰到。

#### C9. Nginx 反代后 API 404、WebSocket / 静态资源错乱、Cookie 路径不对

**现象：** 直连 8000 正常，走 HTTPS 统一入口就不行。

**先查：** location 是否把 `/api` 剥路径剥错；`proxy_pass` 带不带斜杠；Jenkins、门户、API 三个 location 有没有互相抢前缀（artifact 的 CSP 规则必须写在通用 `/jenkins/` 前面，你们已经踩过类似顺序问题）。

**处理：** 统一入口是为了不把 8080/8000 暴露出去；排障时先 curl 本机再 curl 对外路径。

#### C10. 执行机 Python 环境 / checkout 失败，被当成用例失败

**现象：** 门户只看到 failed，日志其实是 pip、venv、git checkout 挂了。

**先查：** Jenkins stage 停在哪：检出、环境、执行、归档、回调。

**处理：** 失败分层，不要一个 error code 打天下。这和项目二「先分环境还是脚本」是同一习惯，平台只是把层显式化。

### 项目三

#### C11. 生成上下文里 similar cases 是空的

**现象：** MCP / API 能通，推荐用例没有。

**先查：** 索引有没有写过；API 读的是不是那份 sqlite；白名单有没有覆盖你问的那条业务；profile 是不是选错。

**部署文档里的原话级原因：** 没 `--write-index`；allowlist 不含目标；读错了库路径。

#### C12. 推荐了其他组的关键字

**现象：** 这是做 MCP 要防的核心事故。

**先查：** 这条关键字为何 `is_allowed`；治理层 deny 有没有跑；生成后 Layer 6 有没有对文本再验。

**处理：** 检索前过滤；生成后静态校验；合入仍靠 Review。面试说「约束是为了这件事」，不要说「从来没漏过」。

#### C13. AST 解析失败，索引缺文件

**现象：** 某个 .robot 很奇怪，整次扫描中断或静默少文件。

**设计：** 官方 AST 解析失败记 `ParseIssueRecord`，继续扫别的文件，不拿正则当生产 parser。

**先查：** parse issues 列表、文件编码、不完整的表格语法。

#### C14. 仓库更新了，Cursor 还在用旧索引

**现象：** 新关键字推完，生成上下文没有。

**先查：** 索引任务是否跑过；构建失败时有没有用 tmp 再 `mv`，避免半成品覆盖好库（部署文档写过）。

**口径：** 构建和查询分开，API 只读库，不边查边全盘扫。

#### C15. 生成稿能 parse，但 Review 一看就不能合

**现象：** 有 Documentation / Tags，却引用了不该引用的 resource，或缺清理步骤。

**处理：** Layer 6 静态校验（不执行、不连设备）；通过也不等于可合入。MCP 产出是参考。

#### C16. 本地 MCP 通、走 Nginx HTTPS 后 query 失败

**现象：** `/health` 可以，生成上下文超时或 body 没转到。

**先查：** `proxy_read_timeout`、请求体是否被丢掉、API 日志。Windows 上 PowerShell 拼 JSON 也容易假失败。

#### C17. 扫描了不该扫的仓库路径 / 权限

**现象：** 索引进了别的组目录或密钥文件。

**处理：** profile 限定扫描范围；只读；不执行 Python。面试强调边界，不要吹扫了全公司。

## D 类：项目二才是「完成态排障」——平台题答完不够时，转这里

面试官要的「真实、反复出现、你关过单」的故事，用项目二更稳，例如：

1. 同一条用例环境 A 稳定、环境 B 偶发：先看环境占用、拓扑、版本包是否一致，再看脚本等待和断言。  
2. 公共库接口变更后组内关键字大批红：先看报错是否集中在同一封装，再适配、小范围回归、通知组员。  
3. 抓包证明空口 / 信令或链路问题，脚本本身绿过关键步骤：归产品或环境，不是盲目改关键字。

讲完可以收：项目一是想少一个环境一个环境点门户；现在平台还没替代这套日常，所以失败分析能力首先是在项目二练的。

## E 类：三套 45 秒口述稿（建议背熟）

### 1. 真实联调（A3，log.html）

> 门户里点 Robot 日志，文件 Jenkins 已经归档了，页面却提示 log 打开失败。我先确认 artifact 在、本机能下到文件，排除没生成。后来发现是 Jenkins 对归档目录默认加了 CSP，禁止内联脚本，而 Robot 的 log.html 靠内联 JS 渲染。我在 Nginx 上只对 artifact 路径去掉 CSP，Jenkins 主界面策略不动。结论是：失败不一定在测试脚本，也可能在「文件怎么被浏览器打开」。

### 2. 真实部署（A1，时间）

> Debian 上 run 时间和我本机差十几分钟，我先怀疑时区，确认已经是上海。再看 NTP，服务开着但访问公网时间源超时，多半是出网策略。先关掉无效自动同步、手工校时，避免拿错乱的时间去判断回调是否超时。平台要对三方记录，时钟也是联调的一部分。

### 3. 完成态高频（C1，状态不一致，承认未全量）

> 如果门户和 Jenkins 颜色不一致，我不会先改业务用例。用同一条任务编号对库里的状态、Jenkins 构建号、最后一次回调。分不清是没触发、执行失败，还是回写失败。所以创建和触发是拆开的，触发失败记录还在，可以重试。完整每天代替人工点二十套环境，我们还没收到那个程度；这条查法是按契约和服务器验证在用的。

## F 类：对方施压时的边界句（直接用）

- 「这两个项目我按 step 在收口，不是已经替代全组日常入口。」  
- 「编码有 Cursor 辅助，问题是我在 Debian / Jenkins 上对出来的。」  
- 「RCA / 生成用例都要人看过才当结论。」  
- 「SQLite、单 Jenkins、资源锁都是当前规模的取舍，不是生产级高可用。」  
- 「回调幂等、真实测试线最后一截、MCP 全组使用，文档里仍有未收口项，我不会讲成已经做完。」

把 A1、A3、A5 和项目二的一个失败例子练顺，比背二十个虚构生产事故更安全。C 类只作为「他追问闭环异常时的答题框架」。
