# 面试问题清单（对照《简历_林XX_自动化测试工程师_通用软件向》）

面向：自动化测试工程师一面 / 二面。按一场完整面试的顺序排，问题都来自这份简历上的字。

用法：先看每节「面试官在探什么」，再按问题口述。不要背稿。简历没写的（例如早间 CIT 分诊 Agent、公共数据）不要主动展开。

作答总原则：

- 项目二是 2019 年起的本职；项目一、项目三是 2024 年后的延伸。
- 「独立完成 / 独立推进」指需求拆解、模块划分、联调验收和部署验证；编码落地借助 Cursor，不要说自己从零手写全部前端。
- RCA、MCP 结论或生成结果都要带「人工复核 / 参考」，不要说已经替代测试判断。
- MCP 是组内辅助，未写成全组上线；被问规模时如实说使用范围。
- 数字（约 20 套环境、约 200 条用例、4 个版本）只讲自己负责范围内能解释清的，不要再放大。

## 0. 整场大概怎么走

| 阶段 | 常见时长 | 简历上会被盯的点 |
|---|---|---|
| 自我介绍 + HR / 开场 | 3–8 分钟 | 12 年、诺基亚、杭州、2026.10 结束、为什么现在看机会 |
| 专业技能扫一遍 | 10–20 分钟 | 精通 Robot Framework、Jenkins、独立做平台、AI、Git、Linux、抓包 |
| 项目二（本职） | 15–25 分钟 | 接口人、可行性、关键字、CIT/CRT/CDRT、失败分析 |
| 项目一（平台） | 15–25 分钟 | 三模块、FastAPI/React/Jenkins 闭环、KPI 对比、RCA、Cursor、Debian |
| 项目三（MCP） | 5–15 分钟 | AST、关键字约束、给 Cursor 的上下文、和项目一 RCA 的区别 |
| 场景 / 现场题 | 10–20 分钟 | 失败怎么分、关键字怎么封装、Git 冲突、Linux 查日志 |
| 反问 + 收尾 | 5 分钟 | 稳定性、到岗、薪资、为什么选他们 |

多数公司会先问项目二（听得懂、好对比），再决定要不要深挖平台和 MCP。投「测试开发 / 平台」时项目一会提前。

## 1. 开场：自我介绍、动机、经历匹配

面试官在探什么：你是谁、为什么离开、能不能讲清楚 12 年而不散、会不会把通信背景讲成「我只会基站」。

1. 请用 2–3 分钟介绍一下自己，以及为什么看这个岗位。
2. 在诺基亚具体做什么？高级和初级两段有什么不同？
3. 「组内自动化接口人」是职称、兼职，还是日常职责？对接哪些人？
4. 为什么 2018 年从 3G 转到 5G 通信系统软件测试？
5. 12 年为什么还投自动化测试，而不是测试经理、开发？
6. 为什么现在看机会？（站点关闭可以说，不要贬低前东家。）
7. 最快什么时候到岗？有竞业或离职手续吗？
8. 期望薪资、接受外包 / 驻场 / 出差吗？
9. 这份简历偏软件测试，实际工作是不是通信协议 / 射频？你和纯软件测试的差别在哪？
10. 硕士是信号与信息处理，和现在做的自动化是怎么接上的？
11. 英语六级之后工作中怎么用英语？（邮件、用例、日志、会议）
12. 中级工程师是什么序列、什么时候评的？和日常工作有什么关系？

口径提示：工作经历那句已经够当自我介绍骨架——5G 通信系统软件测试、自动化接口人、用例实现、Jenkins 日常回归；平台和 MCP 放在「近两年额外做的」即可。

## 2. 专业技能

技能栏是面试官划题的目录。每一条都可能被追问到「你到底做到哪一层」。

### 2.1 自动化框架：Robot Framework、Python、关键字、可行性、多版本适配

面试官在探什么：会不会真写用例和库，还是只会调别人的关键字；「精通」会按中高级来问。

**Robot Framework**

1. 为什么组里用 Robot Framework，而不是 Pytest / unittest？
2. 一套用例的目录一般怎么组织？suite、resource、variable 怎么分？
3. Test Setup / Teardown 和 Suite Setup / Teardown 分别用在什么时候？
4. 关键字写在 `.robot` 的 Resource 里，和写在 Python Library 里，你怎么选？
5. `[Arguments]`、`[Return]`、`[Tags]`、`[Timeout]` 你怎么用？打过哪些 tag？
6. 强制等待和条件等待怎么选？用例不稳定时你先查什么？
7. 变量优先级：命令行、suite、resource、内置，你实际怎么控环境差异？
8. 失败之后去看哪些产物？`output.xml`、`log.html`、`report.html` 你分别用来干什么？
9. 怎么在 Python 里自定义 Library？怎么把失败信息打清楚，方便 CIT 失败分析？
10. 并发跑过吗（pabot 等）？多版本、多环境并行时怎么隔离变量和设备？
11. Listener、timeout、retry 用过吗？用在哪类失败上？

**Python（封装关键字）**

12. 公共关键字用 Python 封装时，你的分层是什么？（设备操作 / 配置 / 校验 / 日志）
13. 举一个你封装过的关键字：入参、出参、失败时抛什么。
14. 异常怎么处理？什么时候该 fail 用例，什么时候该重试？
15. 日志怎么打，才能在 Jenkins 控制台和 `log.html` 里都能定位？
16. 对 Python 熟悉到什么程度？（列表字典、文件、正则、模块、虚拟环境即可，被问到装饰器、生成器、GIL 不要硬撑。）

**可行性分析、用例开发、多版本适配**

17. 一个已手工测完的功能，你怎么判断能不能自动化？哪类功能你会明确不做？
18. 可行性分析会看哪些依赖：环境、仪表、账号、数据、公共库、执行时长？
19. 「多版本适配」具体改什么？关键字、变量、还是分支策略？
20. 4 个版本并行时，代码是一份多配置，还是多分支？冲突怎么解？
21. 公共库接口变了，组内关键字怎么改、怎么回归、怎么通知别人？

雷区：「精通」被追问到 Robot 内部实现、RF 源码、复杂 Listener 时，回到「日常用来写用例和封装关键字」。不要把部门公共库（TAF）说成自己从零写的框架。

### 2.2 持续集成：Jenkins、CIT / CRT / CDRT、执行监控与失败分析

面试官在探什么：会不会把自动化接到每天跑；失败时能不能分类，而不是只会点红灯。

1. CIT、CRT、CDRT 在你们的节奏上有什么差别？（触发频率、用例集、失败处理时限）
2. Jenkins 任务是你建的，还是沿用部门现成流水线？你改过哪些配置？
3. 一次每日 CIT 怎么被触发？定时、代码提交、还是人工？
4. 流水线有哪些阶段？失败停在某一阶段时你怎么看日志？
5. 参数化构建怎么做？版本、环境、用例标签怎么传进 Robot？
6. 凭证、节点、工作空间、产物（log.html / output.xml）存在哪？你怎么取？
7. 20 套环境并行时，Jenkins 怎么分配节点？环境被占用怎么办？
8. 监控是看 Jenkins 页面、邮件，还是自己扫结果？一天大概处理多少失败？
9. 失败分析的第一步是什么？怎么区分环境、脚本、产品问题？
10. 同一条用例连续失败和偶发失败，处理有什么不同？
11. 流水线绿了但业务结果不对，你遇到过吗？怎么发现的？

雷区：不要把「在现有 Jenkins CI 上维护」说成「我从零设计了公司 CI」。不要把未写进简历的早间自动扫 portal 说成已上线能力。

### 2.3 自动化平台：FastAPI、React、Nginx、需求拆解、AI 编码、联调验收

面试官在探什么：你是测试开发，还是「会提需求、会验收、编码靠 AI」；后一种也可以，但必须自己承认边界。

1. 「独立完成需求拆解、模块划分与闭环设计」——需求是谁提的？你输出过什么文档或图？
2. 三个模块（配置调度、任务执行、结果回收）各自边界是什么？为什么这么切？
3. FastAPI 在链路里承担什么？有哪些主要接口？
4. 为什么用 FastAPI 而不是直接让页面调 Jenkins？
5. React 页面有哪些功能？创建任务时要填哪些字段？
6. 前端、接口、数据库字段不一致时，你怎么查？举一次联调问题。
7. Nginx 做什么？反向代理、静态资源、还是 HTTPS？
8. 「借助 AI 完成编码落地」具体怎么用 Cursor？你负责哪一段：提示词、阅读 diff、跑通、修 bug、验收？
9. AI 生成的代码出过什么错？你怎么发现、怎么改？
10. 联调和验收的检查单是什么？怎样算「页面、数据库、Jenkins 记录一致」？
11. 这个平台现在谁在用？是只有你，还是组里别人也从页面点任务？

雷区：不要说自己是全栈工程师。React 状态管理、Hooks 细节、Nginx 调优，会多少说多少。平台挂了你怎么查，比背概念重要。

### 2.4 AI 辅助测试：失败日志摘要、RCA、MCP 辅助写用例

面试官在探什么：AI 是产品能力还是个人习惯；和「用 ChatGPT 问问」有什么差别。

1. 简历里的 AI 做了哪两件事？分别用在什么时候？
2. RCA 的输入有哪些？Jenkins 日志、Python 日志、KPI 报告，权重怎么定？
3. 根因分类有哪些类别？准确率怎么看？错了怎么办？
4. 「结论经人工复核」你具体复核什么？改过模型结论吗？
5. MCP 和 RCA 是不是同一套服务？为什么要做成 MCP？
6. 辅助写用例时，如何避免生成别的组的关键字？
7. 生成的用例能直接合入 GitLab 吗？还是只当参考？
8. 如果没有 Cursor，这套 MCP 还有价值吗？
9. 数据安全：日志和用例会不会出内网、会不会进公共大模型？

雷区：不要把规则分类、人工经验说成「大模型已经自动定位根因」。不要把 MCP 说成已在全部门推广。

### 2.5 Git 与 Code Review

面试官在探什么：能不能在团队仓库里安全改代码。

1. 组内分支策略是什么？你的用例怎么进主分支？
2. 你做 Code Review 时主要看什么？（关键字复用、硬编码、等待、环境依赖、命名）
3. 举一次你在 Review 里拦住的问题。
4. 公共库接口变更导致冲突时，你怎么合？
5. `merge` 和 `rebase` 你实际怎么用？
6. 误提交了环境相关文件或账号怎么办？
7. 提交信息怎么写？一次提交大概改多大范围？

### 2.6 Linux、QC、JIRA

面试官在探什么：会不会上执行机查问题；缺陷能不能闭环。

1. 执行机常用哪些命令查进程、磁盘、日志、网络？
2. 日志很大时怎么搜关键字？如何只看某次运行的片段？
3. 权限不够、磁盘满、Python 环境坏了，你怎么处理？
4. QC 和 JIRA 在你们流程里分别干什么？缺陷状态怎么流转？
5. 缺陷单你会写哪些字段？怎样算复现步骤写清楚？
6. 开发说「我们这边没问题」时，你用什么证据往下推？

### 2.7 功能测试、性能测试、抓包与分层定位

面试官在探什么：自动化之前你是不是真的会测；失败时会不会只盯脚本。

1. 自动化开发前的手工验证，你验到什么粒度才开始写用例？
2. 功能失败和性能失败，分析路径有什么不同？
3. 「抓包 + 系统日志分层定位」请举一个例子：哪一层先看，什么现象对应环境 / 脚本 / 产品。
4. 性能测试在 3G 阶段做过什么？指标有哪些？自动化平台里的 KPI 和当年的性能测试是不是一回事？
5. 兼容性测试具体兼容什么？（版本、环境、配置）

通用向简历弱化了空口和基站细节。对方若按通信协议深挖，可以承认日常是系统软件测试 + 自动化，协议栈不是你的主交付；定位时会用抓包和日志，但不是协议开发。

## 3. 项目一：KPI Benchmark 自动化回归测试平台（2024—2026）

面试官在探什么：你有没有把「跑 KPI 回归」收成闭环；数字和架构能不能画出来；AI / Cursor 会不会成为唯一解释。

### 3.1 背景与收益

1. 没有这个平台之前，组里怎么跑 KPI、怎么收结果、怎么对比？
2. 「减少人工触发、手工收结果、逐条翻日志」分别省在谁身上？有没有量化？（没有量化就说现象，不要编百分比。）
3. 这个平台服务的是 KPI Benchmark，和项目二的 CIT/CRT 是不是同一套执行？
4. 为什么 2024 年才做？是你提议的还是领导要求的？
5. 如果只保留 Jenkins、不做页面，会缺什么？

### 3.2 架构与三模块

6. 请画一下：操作者、React、FastAPI、Jenkins、执行机、结果文件、SQLite 的调用顺序。
7. 配置调度、任务执行、结果回收，各自包含哪些功能和数据？
8. 任务创建之后，状态有哪些？失败、超时、回调失败分别长什么样？
9. 为什么用 SQLite 而不是 MySQL / PostgreSQL？多个人同时点任务会不会锁库？
10. KPI 报告以什么格式回收？存在磁盘、Jenkins artifact，还是入库？
11. 一次任务的唯一 ID 是什么？如何同时对上页面记录和 Jenkins build？

### 3.3 页面 → 接口 → Jenkins → 回写

12. 从页面点「创建 / 执行」到 Jenkins 真正开跑，中间传哪些参数？
13. FastAPI 怎么触发 Jenkins？（API token、crumb、Job 参数）
14. Jenkins 跑完怎么回调？谁调谁？失败谁负责重试？
15. 「与页面、数据库、Jenkins 记录核对一致」你核对过哪些字段？出现过不一致吗？
16. 回调比任务先到、或重复回调，怎么处理？
17. Jenkins 任务还在跑，用户在页面刷新或重复提交，你怎么防？

### 3.4 KPI 对比、趋势、异常标注

18. 基线怎么定？和哪一次历史比？
19. 趋势展示的是哪些指标？异常标注的规则是什么？谁定的阈值？
20. 「辅助判断本次回归是否劣化」——最后谁拍板，平台还是人？
21. 对比模块是你实现的，还是接入组内已有能力？你负责接入、验收，还是算法本身？
22. 出过误报或漏报吗？后来怎么改规则或展示？

口径提示：对比出图、异常标注可以讲平台接上了报告分析和展示；不要主动把统计方法（t 检验、控制图等）讲成自己的算法论文。被问到实现细节，按「规则 / 接入 / 验收」说清自己的边界。

### 3.5 RCA

23. RCA 在任务成功时跑还是只在失败时跑？
24. 摘要、分类、修复建议各长什么样？给谁看？
25. 人工复核的流程：你在页面上改结论，还是只在脑子里判断？
26. 修复建议有没有被开发或同事采纳过？举一个有用和一个没用的。
27. 如果大模型不可用，平台是否仍能完成调度和收结果？

### 3.6 Cursor、部署、排障

28. 哪些模块是 Cursor 辅助写的？哪些是你手改的？
29. Debian 上怎么部署？进程怎么保活？配置文件放哪？
30. Nginx 和 FastAPI 怎么配？静态页面和 API 怎么分路径？
31. 举一次部署或联调问题：现象、你查了哪几层、结论。
32. 平台挂了，KPI 回归还能跑吗？

现场可能让你：画架构、写一个假的回调 JSON、讲一次失败排查。准备一张能画在白板上的简图。

## 4. 项目二：Feature 自动化用例开发与 CIT、CRT 回归（2019—2026）

这是多数面试官认定的「你到底会不会做自动化」的项目。数字和接口人职责会被逐项核对。

### 4.1 角色与范围

1. 小组有多少人做测试、多少人写自动化？接口人一天实际在干什么？
2. 「约 20 套测试环境、约 200 条用例、4 个版本」请拆开：这些是否都是你一个人维护？
3. 200 条是 Robot 用例数、测试点，还是标签下的集合？新增和淘汰怎么管理？
4. 4 个版本并行，CIT 是每天每个版本都跑满，还是有优先级？
5. 2019 年到 2026 年，这套回归最大的变化是什么？

### 4.2 从手工到自动化

6. 手工用例转化成自动化的标准流程是什么？
7. 可行性分析请举一个「做了」和一个「没做」的功能，原因分别是什么？
8. 环境依赖和复用方式，你在分析阶段会写成什么，给谁看？
9. 公共关键字是先规划再写用例，还是写着用着再抽？
10. 自动化开发前的环境搭建，你搭的是执行机、被测环境，还是两者都有？

### 4.3 关键字与 Robot 用例

11. 组内公共关键字大概分几类？举 2–3 个名字和用途（不必泄密内部模块名，用职责描述即可）。
12. 和部门公共测试库是什么关系？你们封装的是业务层，还是对公共库再包一层？
13. 公共库接口变更时，你怎么发现、怎么改组内关键字、怎么验证兼容？
14. Code Review 你有没有拒绝合入的权力？分歧怎么收？
15. 一条典型 CIT 用例的结构：准备、操作、校验、清理。校验断言写在哪一层？
16. 数据驱动做过吗？多版本差异是用变量文件还是 tag？

### 4.4 CI 日常与失败分析

17. 请按时间讲一个「昨天 / 典型一天」的 CIT：何时看结果、失败怎么分、什么时候提单。
18. 环境问题、脚本问题、产品问题，请各举一个真实例子（现象 + 证据 + 结果）。
19. 抓包在失败分析里什么时候用？哪类问题不用抓包？
20. 缺陷跟踪到关闭，你还做什么？会不会验证修复后再加回归？

### 4.5 和项目一、项目三的关系

23. 项目二的 CIT 失败，会不会进项目一的平台？还是两套体系？

## 5. 项目三：组内 Robot Framework 用例 MCP 知识服务（2025—2026）

### 5.2 索引与约束

### 5.3 MCP 与 Cursor
