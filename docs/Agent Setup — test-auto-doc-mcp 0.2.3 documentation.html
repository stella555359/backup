    Agent Setup¶

    TL;DR¶

    For better UTE TAF MCP usage:

    Copy the .cursor/rules and .cursor/skills tree from test-auto-doc-mcp-setup into your own .cursor/ directory.

    Rules and Skills¶

    Installing the MCP server makes the tools available, but an MCP-capable agent (Cursor, Claude, etc.) does not automatically know when to call them, which vectorstore to query, or how to interpret Nokia-specific terms. Without that context the agent often skips MCP lookups and answers from its own training data, which leads to stale, partial, or fabricated answers — especially for acronyms (SBTS, vCU, COAM, UTE, etc.) and TAF library contracts.

    Pairing the server with dedicated Cursor rules and a task-triggered skill significantly improves the precision of MCP tool invocation: the agent reliably recognises when a question is in scope, selects the right tool, and grounds its answer in authoritative documentation instead of guessing. They are the difference between “the agent guesses” and “the agent retrieves the source of truth.”

    Rules and Skill Overview¶

    File

    Scope

    Purpose

    01-nokia-domain-knowledge.mdc

    Always-on vocabulary

    Nokia domain acronym dictionary (TAF, UTE, SBTS, vCU, vDU, gNB/eNB, COAM, SCF, NETCONF, OAM, RFRL, WTS, UE, UEVT, NetAct, etc.) plus TAF library naming conventions (taf.*, ta_*, ta5g_*, rfsw.*) and lifecycle statuses (lead, active, deprecated). When any of these terms appears in the user’s message, the agent must treat it as a Nokia-domain topic and consult the Knowledge Base via MCP instead of relying on generic knowledge.

    02-knowledge-base-exploration.mdc

    Search methodology

    Mandates an agentic search process — Decomposition → Deepening → Exploration → Coverage check — before the agent answers any factual question. Forces the agent to expand keywords with synonyms, abbreviations, and related concepts, follow cause → effect / part → whole / problem → solution threads as independent leads, and keep searching via MCP until definitions, limits, steps, and edge cases are all covered.

    ute-taf-mcp-agentic-flow

    Task-triggered TAF workflow

    Binds concrete TAF workflows (code changes touching taf.namespaces.*, troubleshooting library failures, API/usage questions) to the test-auto-doc MCP tools listed above. Tells the agent how to degrade gracefully when the MCP server is unavailable (retry once, then warn the user the answer may be incomplete before falling back).

    Where to Install the Rules and Skill¶

    Mirror the layout used in the source repository (test-auto-doc-mcp-setup).

    Cursor loads rules and skills from two locations. Pick the one that matches how widely you want the guidance to apply:

    Scope

    Location

    When to use

    Project

    Rules: <repo-root>/.cursor/rules/<rule-name>.mdc
    Skills: <repo-root>/.cursor/skills/<skill-name>/SKILL.md (plus any supporting files in the same folder)

    Commit the files alongside the codebase so every contributor (and CI agents) get identical guidance.

    User (global)

    Rules: ~/.cursor/rules/<rule-name>.mdc
    Skills: ~/.cursor/skills/<skill-name>/SKILL.md (plus any supporting files in the same folder)

    Enable the guidance across all projects you open in Cursor, even repositories that do not ship their own .cursor/ directory. Useful when you work on several TAF-adjacent repos or want the rules active in ad-hoc scratch projects.

    Both locations can coexist — project-scoped files take precedence and user-global files act as a fallback. Place each rule file directly under rules/; place each skill in its own folder under skills/ (named after the skill, containing SKILL.md plus any supporting assets) so related files stay grouped together.

    Example layouts:

    # Project-scoped (committed with the repo)
<repo-root>/.cursor/
├── rules/
│   ├── 01-nokia-domain-knowledge.mdc
│   └── 02-knowledge-base-exploration.mdc
└── skills/
    └── ute-taf-mcp-agentic-flow/
        └── SKILL.md

# User-global (applies to every workspace)
~/.cursor/
├── rules/
│   ├── 01-nokia-domain-knowledge.mdc
│   └── 02-knowledge-base-exploration.mdc
└── skills/
    └── ute-taf-mcp-agentic-flow/
        └── SKILL.md

    No extra configuration is required — Cursor auto-discovers files under these paths on the next turn.

    Why Both Rules and a Skill¶

    • Rules are always-on: they load on every turn and shape how the agent interprets the user’s message (domain vocabulary) and searches (exploration methodology). They act as a precondition — without them the agent may not even recognise that the question is Nokia-specific, let alone reach for the MCP.

    • Skills are task-triggered: they activate when the user’s intent matches the skill’s description (e.g. editing TAF code, debugging a TAF library). They bind that intent to a concrete MCP call sequence.

    Using them together closes the loop:

    1. A rule recognises taf.sw.neat or COAM as a Nokia domain term.

    2. A rule forces a decomposed, multi-term search plan.

    3. The skill routes that plan through the correct test-auto-doc MCP tools.

    4. The agent answers from authoritative documentation, with real citations, instead of guessing.
